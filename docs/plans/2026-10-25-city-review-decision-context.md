# Put city identity evidence on the decision page

Audit of the largest remaining lifecycle group found 867 private placeholders: 577 have no venues or events, but only 27 are completely unlinked across the existing relationship guard. The other 550 apparently empty records still have other relationships. Zero venues/events therefore cannot justify treating these cases as unused records.

The existing case detail RPC supplied current records for events only. City identity cases received null and displayed generic research JSON. Add a city-only context payload after the existing staff, case and per-source checks. Include stored country/region/coordinates, lifecycle/indexing, current identifier, source-coordinate evidence, retracted identifier reason, current classification/geography sources, record timestamp and 15 relationship count groups. Counts cover all relationship tables in the existing inactivity guard. Deduplicate news references stored in both supported representations. Return only a combined count for saved/private links, without user identities or private record content. Do not change cases, city records, decisions or permissions.

The page now shows readable identity facts, links to the stored and captured-source pins, explicit retracted-identity context and related records including biographies/news/organizations. Missing counts remain unknown; only a complete all-zero count payload is labelled empty. Invalid or missing coordinates never become zero. Validate source URLs and Wikidata IDs before creating links. Keep full research history available below the summary.

Validation: eight frontend tests cover city identity, conflicting source information, missing context/counts, zero coordinates, unsafe links and existing case behaviour. Scoped ESLint passes. Disposable PostgreSQL tests cover all 15 relationship groups, news deduplication, cross-city exclusion, private aggregates, staff/case/source authorization, browser denial, missing records and unrelated case families. A rollback-only temporary helper also read the actual native schema and demonstrated the Salem Wisconsin/Oregon conflict without changing production schema or data. Desktop and mobile previews used that public-place example: no horizontal overflow or runtime errors in either bounded inspection round. Full project type checking reports 687 diagnostics, none in changed source files; it is not a clean project-wide typecheck.

The migration and UI require normal protected deployment. No live queue reductions are claimed for this change. Preview artifacts remain in .tmp/city-context-desktop.png and .tmp/city-context-mobile.png. Existing dependency files were reused through local symlinks; no packages were installed or shared dependency files changed.
