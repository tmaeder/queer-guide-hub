# Recover explicit event formats from captured publisher titles

The remaining category cohort had 248 cases. The broad classifier can propose a format from incidental description text (for example a youth art showcase hosted at a theatre), while the event remains `other`. This rule corrects a narrow subset whose unchanged captured publisher titles explicitly name a supported format.

Only exact format phrases are supported: drag show/brunch/bingo, board game night, support/discussion group, book club, specified climbing/running/swimming/pickleball activities, painting/meditation class and art showcase. Matching two different formats refuses the record. Generic audience, nightlife, musical title, party, pride, fetish and description keywords do not drive this correction. Other categories remain available for review.

Require the same event ID, native external ID, source adapter ID, captured title, source timestamp and start date. Qcal additionally requires matching raw title, slug and exact publisher URL. Ticketmaster requires its normalized name, source adapter and Ticketmaster ID. Refuse duplicate source bindings, malformed hashes/dates, human field ownership/revisions, manual issue holds, reviewed/accepted/resolved findings, duplicates and non-neutral current categories. Lock the native event, issue and source rows. Change only event_type, its provenance and updated_at; assert the protected event projection and unrelated provenance are unchanged. Resolve only the obsolete native category finding, preserve other findings and publication settings, and retain complete event/issue before-and-after audit rows.

The migration installs a private, service-only reconciler on the existing five-minute automatic-resolution hook. It composes with the publisher-copy hook, honors the shared pause and lock, caps each call at 100 and is idempotent. Normal protected deployment is still required. No new cron job is created.

The operator reads the exact two function definitions from the migration, changes their namespace to pg_temp, and runs a bounded transaction in dry, rollback rehearsal or apply mode. It drops the temporary functions before committing. It never installs permanent production schema. Credentials remain in the existing CLI keychain and are never printed. A failed/unknown native response must be checked against authoritative state before retrying.

Validation: 31 source/ownership fixtures, ambiguous format counterexamples, dry/batch/zero/pause/browser-denial checks, hook composition, preservation of unrelated issue codes, full-row protection, audits and idempotency passed in a rollback-only pg_temp fixture transaction. Local initdb could not complete because of shared disk exhaustion; the hosted fixture fallback creates no public objects or data. Native dry and rollback rehearsal each found 18 eligible events. Apply corrected all 18 with 36 audit records. Independent native hashes confirm protected content, dates, coordinates, relationships, publication and unrelated provenance unchanged for all 18. Refreshed admin_review_cases records show all 18 category cases inactive, with zero corresponding open native category findings. Nine events retain unrelated review cases. A follow-up dry run returned zero remaining candidates. This is 18 removed cases, not 18 fully reviewed events.

Receipts: .tmp/source-event-format-dry.json, .tmp/source-event-format-rehearsal.json, .tmp/source-event-format-applied.json, .tmp/source-event-format-exhausted.json.
