# Meet: find company

Approved by the user on 2026-11-25 after reviewing the deployed consolidation.

Meet answers “Who can I do something with here?” It is an Operate surface in the existing paper, ink and subway visual system.

- `/meet` becomes the existing invitation experience for locals, visitors and event companions. Travel is context, not another app. Existing `/meet/travel` links remain compatible and new trip/event links enter `/meet` with context intact.
- One primary row: Meetups, People, Groups, Dating. Dating retains signed-in visibility and explicit opt-in. Nearby is a deliberate map action, not a second navigation row. Connections remain in Hub.
- Compact title, city/activity/date controls and one primary “Suggest a meetup” action. Browsing can use a visible next-two-weeks default; publishing still reviews concrete dates and requires fresh consent. Keep private trip references, server safety gates, moderation and accepted-request Messages intact.
- Remove the featured-group hero, full directory, venue catalogue and large connection map from the opening page. Show invitations first, then clearly distinguished event/group opportunities. Never substitute broader geographic results without saying so.
- Keep loading, error, signed-out, empty and restricted states distinct. Authentication preserves context and drafts; browsing does not publish presence or invitations.
- People uses the same compact frame and an inline sign-in prompt rather than an oversized panel. Filters remain progressively disclosed. Use incumbent tokens, accessible labels and responsive controls.

Validation covers root and legacy entry, explicit city/trip/event continuity, default versus chosen dates, invitation consent/auth return, one active primary navigation link, and desktop/mobile hierarchy. No schema changes or new social data model.
