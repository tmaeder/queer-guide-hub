# Close exact repeat news submissions without republishing

The remaining RSS queue had 521 pending review submissions. An indexed exact-URL audit found 245 already represented in nonduplicate catalogue articles. URL equality alone is insufficient: 69 catalogue articles were rejected, some submissions requested manual review, and others contained different extracted source content. An initial OR join including unindexed canonical_url was cancelled after confirming the exact read query was still active; the bounded indexed URL audit then completed normally.

The final rule found 16 untouched machine submissions carrying identical publisher input. Require the same exact HTTPS story URL in raw/normalized/catalogue data, publisher ID, publication timestamp, original headline fingerprint, SHA-256 source body, normalized feed body, media type, audio URL and image URL. Refuse new source content, aliases/redirect guesses, multi-URL payloads, malformed dates, existing match candidates, human revisions/notes/reviews, manual holds, active source recovery, pending entity-link decisions, satire and advertorial flags. The catalogue article must still pass the existing news publication-policy helper with an explicit positive decision and no blocked reasons. The staged decision must also be positive and not request manual review. Source identity is demonstrated independently of model relevance/confidence scores.

Resolve the repeated submission as skipped/duplicate, binding both the target and dedup match to the existing article. Retain its pending_review review_status, raw/normalized/enriched content and all machine quality findings. This does not approve the staged verdict or reject the catalogue article. Never write or republish the catalogue article. Row locks and full-row assertions protect both source evidence and catalogue content. Store a complete before/after staging audit plus the exact source fingerprints and unchanged catalogue hash.

The service-only reconciler composes with the existing automatic cleanup return expression, shared pause and lock. Each call is capped at 100. The operator executes the exact definition in pg_temp with dry, rollback rehearsal and apply modes, drops it before commit, and writes atomic receipts. No permanent production schema was installed during factual catch-up. The recurring hook awaits normal protected deployment.

Validation: all 32 isolated source/quality/manual-ownership cases passed, alongside pause, bounds, browser denial, hook composition, no-publication mutation, complete audit and idempotency checks. Native dry and rollback rehearsal each matched 16 candidates. Apply skipped all 16 duplicates. Independent verification found 16 correct canonical bindings, 16 byte-for-byte unchanged catalogue rows, 16 unchanged protected staging projections and 16 audit records. After refresh all 16 corresponding admin_review_cases rows were inactive. Follow-up dry found zero candidates. Other URL matches remain pending.

Receipts are retained under .tmp/exact-news-source-{before,dry-v2,rehearsal,applied,exhausted}.json. During the enforced release window, 26 specifically identified task-owned obsolete PR validation runs were cancelled and independently confirmed cancelled. Completed evidence, deployments, unrelated checks and the coordinating release checks were untouched. All required gates must run again after the final release-base sync; this branch is kept local until that window clears to avoid starting another obsolete CI batch.
