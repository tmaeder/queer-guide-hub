# Current event artwork reuse

Production had 1,022 open `IMAGE_CONTENT_REUSED` findings, including 462 on declared recurring events or series. The SQL scanner already excludes these events from its URL-reuse warning, but the external image auditor counted every historical observation and ignored recurrence. An event with several observations could therefore inflate a cluster, and replacing an image did not remove its old observation from the count.

The service-only assessment counts distinct canonical, non-cancelled events whose current primary image still has that successfully observed content hash. A recurrence exemption requires EVERY current event in the hash cluster to share one nonempty declared series key. A recurring flag alone, one unassigned peer, or one different series cannot qualify. Ten unrelated current events still trigger review. A primary image changed during a worker run stops that stale reuse result. Evidence retains its existing fields so unchanged accepted findings do not reopen solely because a contract marker was added.

No artwork, content, publication, safety, verification, or quality score is changed. After deployment, targeted native image audits will re-probe the affected records and resolve only findings no longer emitted by the detector. Other image findings remain independent. Ordinary scanning must then confirm that the retired recurrence findings do not reopen.

Validation: 17 isolated PostgreSQL cases cover the threshold, recurrence without a series, wholly single-series versus mixed/unassigned peers, multiple observations per event, replaced primary images, cancelled/merged peers, failed observations, stale/missing targets, malformed hashes, and service-only permissions. The Deno entrypoint check and scoped ESLint passed.

Production deployment 40027316390 installed the initial assessment. Native cluster inspection then revealed one image shared by 422 events across different series, so the initial recurrence policy was too broad. No content-reuse findings had been cleared during that interval. The worker was immediately tightened (v86) to reject a recurrence exemption unless the assessment explicitly proves a wholly single-series cluster. Follow-up migration 99991792791040 implements that stricter proof. Targeted re-audits and final refill verification are still pending.
