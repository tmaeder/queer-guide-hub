# Out x Out official-date checks

Backend pipeline: `outxout-official-date-review`. Worker: `outxout-official-dates`. This is separate from the Out x Out catalogue importer and covers the fixed 21 pending 2027 events in `cohort.ts`.

The weekly start runs Wednesdays at 09:00 Europe/Zurich. Two UTC hours plus a Zurich due guard handle daylight saving; a same-week guard prevents duplicate reviews. The five-minute continuation invokes a cheap authenticated resume; idle calls do no source/model work. Both schedules are registered in `admin_automations` with matching effective cron commands. HTTP request tracking is finalized through `X-Automation-Run-Id`. When all cohort dates are resolved, both backend schedules disable and unschedule themselves.

A run uses bounded public fetches, explicit official links and organiser-linked ticket sites. Source failures are retained, never interpreted as cancellation. Full source captures with retrieval time/hash, candidate passages, typed requests/answers and per-event checkpoints live in the admin-only `admin_automation_runs.summary` ledger. Public pipeline context contains aggregate counts and a ledger ID. Source captures are reused only within six hours. External page text never becomes instructions or SQL.

Code extracts explicit dates; TypeSafe selects a candidate at probability/confidence >= .95. Independent affirmative judgments must each reach .97 and adverse judgments must each be <= .03, matching the project's existing public-field evidence policy. The model cannot invent a calendar date. Parent festival dates cannot confirm a child programme. Unknown, provisional, conflicting and other-city evidence stays pending.

Approval transactions lock and re-read canonical events, all Out x Out staging aliases, relevant review cases and claims, quality issues and generic review items. Optimistic fingerprints reject intervening edits; manual/official field provenance is protected. Approval updates date-only UTC-midnight sentinels, removes stale TBC/descriptive dates, preserves previous values and raw payloads, journals alias changes, and resolves only date-unconfirmed reviews. Other blockers preserve pending publication. Detailed evidence stays private; public provenance uses factual dates, source URLs and hashes.

The worker owns a durable pipeline run and private expiring lease, processes at most three events/request, retries worker/provider failures three times with backoff, and resumes after interruption. Event changes and their durable checkpoint commit together, so unknown outcomes are reconciled before retry. Paused/cancelled runs and disabled automation rows are not resumed. The shared executor route supports admin Run/dry-run; the scheduler calls the dedicated worker directly and has no shared-executor dependency.

Deploy the new function with its pinned dependencies and existing shared helpers. Patch the shared executor against its current live version, preserving other source routes and reliable-step changes. No migrations or SQL DDL are needed. Operator scripts under `scripts/data-quality` register/activate the automation as DML; do not replay them on every deploy. `privatize-outxout-official-date-evidence.sql` is an idempotent one-time transition for initial verification history.

Authenticated POST diagnostics: `{ "probe": true }`, `{ "model_probe": true }` (synthetic typed positives/negatives, experiment budget), `{ "test_contract": true }` (real rollback-only transactions; run only while worker idle), `{ "dry_run": true }` (read-only source preview). Normal manual start is `{ "mode": "manual" }`; scheduled start uses `weekly`, continuation uses `resume`. Callers cannot provide arbitrary targets, source URLs, SQL or approved dates. Internal secret, service-role bearer or admin authentication is required.
